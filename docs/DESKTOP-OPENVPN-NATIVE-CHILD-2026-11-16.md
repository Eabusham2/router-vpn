# Desktop OpenVPN execution child — November 16, 2026

The desktop native child now consumes the original typed OpenVPN Server or
Compare preparation for the bounded ordered graph: one or more paired WG/AWG
prefixes, an independently provisioned OpenVPN member, and the paired SS2022
final. The child uses the same retained execution, physical-policy, selected
proof and teardown owners as the existing desktop host. This continues the
recovered external-node/ordered-path and Local/Server/Compare requirements;
it does not establish every requested graph or a complete installed product.

## Captured native ownership

The child validates the original preparation, physical source, native and
policy pointers, and both captured OpenVPN configurations before construction.
Its context-bound owner rechecks those identities and cancellation before
use. Linux, Windows and Darwin physical adapters retain the existing owned
network policy and teardown; the imported OpenVPN remote does not acquire an
unrelated direct-network permission. Partial construction retains its cleanup
owner. Typed adoption, Ready and Last records use the shared validators
published in `8177db3c`; restoring Last retains the already-proved execution.

The native builder requires the new source, lifecycle, longest-route, Box and
compiled-control phases. The current desktop CONNECT gates and Apple layered
inputs remain intact. The separate public controller/editor integration is
not included in this component publication.

## Executed evidence

The actual complete pinned native core was prepared by the shipping preparers
and compiled with race instrumentation on Linux. No reduced native package
substitute was used. The following **116 native test records** passed across
twelve roots:

The six independently generated real shared-source fixtures and their producer
root also passed in each phase. These repeated seven-record producer runs are
not counted as additional native records.

Three separately compiled controls failed with their exact intended witnesses:
an incorrect schema dispatch lost the typed source; removing the original
physical-pointer check admitted a replaced construction; removing the Ready
error guard admitted a substituted owner or proof. Compiler errors, timeouts,
races and unrelated failures cannot satisfy these controls. Nine runner tests
also validate exact inventories, missing or forged source and receipt rejection,
and mandatory shipping registration.

The original 120-second Go test, 600-second native process, 45-second child
admission and phase bounds remain. The four longest observer leaves completed
in 5.28–5.73 seconds. An initial longest-route fixture incorrectly generated a
96-digit password; it now uses the existing canonical 48-digit format. Strict
production validation was preserved. The first retry compiled successfully
but ran out of scratch space before observation. That failure is retained;
the successful retry used the same corrected source after recorded retirement
of reproducible build cache.

## Evidence still required

Lifecycle cases explicitly model TUN, physical activation and selected-path
proof callbacks. The Box cases use real unstarted managers and do not prove
encrypted provider traffic. Declared Windows/Darwin inputs executed on Linux;
they do not establish native execution on those operating systems. Exact-SHA
hosted builds and package execution, public controller/editor acceptance,
installed kernel/firewall behavior, physical-device networking, signing,
private deployment and whole-release publication remain separate checks.

## Original desktop gate source inventory

The shipping native builder invokes the original OpenVPN owner gate with
`--tagged-only`. Its source verifier previously used the mobile CONNECT file
inventory, although the canonical desktop preparer intentionally omits those
mobile bridge files and includes the desktop reference peer. The verifier now
uses an explicit desktop inventory for that existing caller. Missing files do
not select a mode; the default mobile inventory is unchanged.

All 12 OpenVPN runner tests and the original 14 owner runner tests passed.
The inventory test removes and changes each required file in both projections
and rejects the opposite projection. An independent check of the actual
canonically prepared desktop core reproduced the old missing-mobile-bridge
error and passed the explicit desktop verification, with source identity
`fc2aeed1be5e30336b2f5b278f1cc91641d12153207e9e5209a734746c14a543`.
This repairs source verification before the existing native gate; it adds no
runtime claim and changes no test deadline or production owner.
