# Android connected typed candidate ownership — 2026-11-16

## Shipping behavior

`AndroidNodeCandidateMeasurement` dispatches an original connected Local SOCKS or
HTTP/HTTPS CONNECT capture to its corresponding native candidate factory. It
retains the original typed owner, CommandServer, complete captured source and
selected packet prefix. Generic connected parsing remains closed to those typed
sources. The imported member and final node remain invalid candidate-prefix
positions.

Each typed constructor returns a unique reserved handle before fallible
preparation. Java stores that handle before `Prepare`, so a failed preparation
can retire only its own operation. A refused same-key constructor has no handle
and cannot close an existing operation. Cleanup retains the original candidate
and MTU activity until cancellation, callbacks and native close join. A closed
old handle cannot retire a replacement slot.

Temporary saved-prefix measurements remain purpose-first: they start only their
own prefix service. Their typed suffix is captured provenance and is not started
or borrowed for cleanup. Server and Compare remain outside this connected Local
dispatch. The ordinary constructor contract is unchanged in this unit; its
separate reservation follow-up is not included.

The original fifty-sample scoring, operation deadline and result freshness
bounds remain. The chooser compiles the complete proposed replacement profile
through the actual shared compiler, retains the captured suffix and source
references, and saves a future profile without changing the active connection
or rerunning Compare. A row must have its own complete score before Save.

The AAR verifier checks both exact generated factory signatures and every used
typed-handle method, including `Prepare`. The new Android source/service job is
mandatory in the workflow's dependencies, result environment and success
predicate. All prior jobs, including the layered-candidate job, remain required.
