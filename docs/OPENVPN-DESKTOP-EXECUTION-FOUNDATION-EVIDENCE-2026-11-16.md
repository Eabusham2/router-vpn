# Desktop ordered OpenVPN execution foundation — 2026-11-16

This unit binds typed schema-5 Server/Compare preparations to the original desktop physical policy. It preserves the original plain Local source and independently paired Server descriptor, the native desktop graph, original packet-prefix positions, physical DNS/bootstrap policy, configured ceiling and restored TUN MTU, and the exact concrete winner stored in Last. It does not enable desktop public admission or claim a native desktop host, TUN, installed-device or deployment pass.

## Ownership and serialization

`NewDesktopNodeChainOpenVPNExecutionPreparation` accepts only an original validated `DesktopNodeChainPolicy`. The new concrete physical policy retains exact preparation, original policy, plain source and native-chain pointers. Equal-value reconstruction and copied wrappers do not transfer that authority. Its configuration derives from the original native physical graph; source identity remains the original plain schema-5 source with its sealed Local launch and independent provider pair.

The desktop preparation adds a distinct `desktop_openvpn` metadata field, and restored Last additionally retains `desktop_last`. Generic/mobile parsers remain closed to these fields. A future desktop native constructor must bind this concrete physical owner to the actual original Box, endpoint, process/network and joined close receipt. The existing mobile four-field construction boundary remains independent.

The three target-OS source matrices cover every total length from three through eight, both Server and Compare, mixed WG/AWG packet-prefix modes, TCP/UDP OpenVPN and independent final layers. The current component runtime uses actual loopback proof/lease/measurement/Last controllers with an explicit native boundary double. That evidence does not replace actual encrypted OpenVPN or privileged host acceptance.

## Fresh validation and bounded runtime

A desktop binding validates its original desktop policy once per fresh read. That original policy validates both its plain source and native physical chain; plain/mobile execution retains its separate original source validation. All exact pointers, seals, pair fields, fresh native observations, proofs and cancellation checks remain mandatory. A compiled omission of the original desktop validation admitted a changed native configuration and was rejected by the negative test.

The typed Last wrapper captures exact original projection/preparation/binding/physical/policy/source/native pointers across the unchanged core Last operation. The core performs saved-record validation, proof verification, fresh current and health observations. The wrapper requires the same pointers and live context before returning that original record. A mutation during Last observation must refuse rather than export a saved record.

Desktop preparation seals freshly hash the raw bytes of source JSON, configuration, Local source, sealed Local launch and saved Last on every read. Named fields, byte lengths and SHA-256 values, all remaining typed metadata, source/configuration hashes, DNS and physical captures are bound under a separate desktop-only domain. This avoids repeatedly JSON-escaping large already-encoded strings. It does not cache validity, hashes or live proof; serialized source identities are unchanged. Mixed mobile/desktop authority cannot receive this seal.
