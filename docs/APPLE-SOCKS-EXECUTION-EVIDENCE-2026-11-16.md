# Apple SOCKS5 Server and Compare execution

## Shipping path

The iPhone and iPad ordered editor and complete connection profiles now admit
the distinct SOCKS5 execution family for an exact three-node path: one paired
WireGuard, AWG Fast or AWG Strong entry, one literal-address imported SOCKS5
member, and an independent paired Shadowsocks 2022 final. The original
authentication choice, credentials, member identities, DNS and device policy
remain captured. The existing three-to-eight-node Local SOCKS5 path remains
available through its own source and runtime.

`IOSNodeChainSOCKSCapture` retains the requested execution separately from its
complete Local source. `IOSNodeChainExecutionCapture` is a closed union of
ordinary, CONNECT and SOCKS captures and calls the distinct SOCKS preparation,
launch and Last constructors. It verifies the complete returned member and
identity arrays, source digests and requested execution. Ordinary constructors
cannot lend SOCKS authority. Presentation validates the original final private
profile after removing only the existing scheduling fields.

The existing PacketTunnel starts `RouterNodeChainSOCKSExecutionNewCommandServer`
through `RouterVPNLibboxEngine`. The existing owned execution host retains the
server, binding, proof, measurements, MTU, cancellation and joined cleanup. A
second system VPN is not involved. Saved Last and temporary restoration retain
the already-proved Local/Server choice, complete original source and joined
native restore capsule. They do not rerun Compare selection.

The selected-path latency host now accepts every validated execution family
supported by its shared measurement API. The previous CONNECT-only condition
also prevented ordinary paired and imported-Shadowsocks execution from using
this host. Member roles now come from the captured `node_kind`, so a paired
penultimate member is not mislabeled as an external public path. Original
source, configuration, node, lease, MTU, session and current-owner checks remain.

## Acceptance and remaining requirements

Exact-current generated Apple bindings, full Xcode app and PacketTunnel builds,
encrypted Server/Compare networking, package provenance and publication remain
separate release evidence. Physical VPN permission, selected-path DNS, leaks,
network transitions, visual checks, signing and distribution still require
their corresponding device or environment observations.

Longer SOCKS Server/Compare routes, other imported positions, multiple imports
and additional requested graph families remain accountable to their own
implementation and evidence. Refusal of an unsupported graph does not complete
that requirement. This change does not establish a full release, private
deployment or full-product acceptance.
