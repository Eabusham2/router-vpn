# Android SOCKS5 Server and Compare execution

## Implemented path

The Android ordered editor, saved connection profiles and connection service
now admit the distinct schema-3 execution preparation for an exact three-node
path: one original paired WireGuard, AWG Fast or AWG Strong entry, one
literal-address imported SOCKS5 member, and an independent paired Shadowsocks
2022 final. The SOCKS5 member retains its original authentication choice and
credentials. Its UDP association remains separate from CONNECT's UoT-v2
transport. The existing three-to-eight-node Local SOCKS5 composition remains
separate.

Saving Server or Compare validates the complete original source through
`NewRouterNodeChainSOCKSExecution`. The returned preparation must retain every
original member, paired identity, requested execution and configuration. The
connection capture accepts only the distinct SOCKS execution launch kind; the
ordinary and CONNECT launch constructors cannot borrow that authority.

`AndroidNodeChainSession` creates the execution's original native CommandServer
through `RouterNodeChainSOCKSExecutionNewCommandServer`. The existing single
VpnService retains that server and execution owner through binding, proof,
selected-path measurements, latency, MTU, history, cancellation and joined
cleanup. The dormant Local SOCKS source cannot claim those operations. Failed
native cleanup retains the original owner and receipt requirement.

Last and temporary restoration keep the original requested and already-proved
Local/Server choices. Restoration requires the joined native mobile capsule,
complete original source and current host ownership; a foreign capsule cannot
start the native service. Compare's existing same-endpoint two-probe average
and fresh selected-path proof remain unchanged. Complete profile Add/Load
retains private node references without copying proxy credentials into the
saved profile record.

The actual shared CommandServer, typed MTU and restoration implementation and
its native-object tests are recorded separately in
[the shared mobile evidence](SOCKS-MOBILE-EXECUTION-EVIDENCE-2026-11-15.md).

ordered editor callbacks against the actual shared Go compiler. Native Run,
leases, TUN and restoration are explicit refusing boundaries in that gate.

```sh
python3 android/test_android_socks_execution_capture.py
```

It passed 216 positive compiler/store/editor checks, six unsupported longer
execution refusals and five substituted readback refusals. The positive matrix
contains WG, AWG Fast and AWG Strong, Server and Compare, and both SOCKS5
authentication choices. Checks cover canonical replay, distinct launch
authority, complete profile roundtrip, source replacement and credential
reference ownership. Two separately compiled causal controls remove the
original member or identity comparison and must fail at the specific
substitution witness.


restoration checks. Native handles and Android OS operations are explicit

The existing CONNECT execution suite also passed its 213 lifecycle and 24
restoration checks with all three compiled causal controls. The existing Local

branches; the rejection cases and native close receipt requirement remain.

The original ordered-execution source gate also passed 459 source/profile

The existing candidate-prefix host gate passed 77 shipping Java checks and

The required Android workflow runs both new scripts. The workflow contract

## Evidence boundary and remaining scope

These results establish the actual shared source/compiler and shipping Java
host composition described above. Java host models do not prove an Android
TUN, encrypted traffic, a remote server lease, physical routing or device
acceptance. Exact-current generated bindings, APK builds and encrypted native
gates remain separate release requirements. Physical permission, leak,
reconnect, network transition, visual, signing and upgrade acceptance still
require their corresponding evidence.

The broader existing `ordered-chain` source suite did not complete within its
180-second aggregate command limit on this local host. A diagnostic run kept
every case and the same limit and isolated the cost of the existing 40 MiB
aggregate-budget fixture and subsequent imported-source matrix. It reported no
source assertion failure before the timeout. This is an incomplete local
regression result, not a pass; the original limit and full CI gate remain.

Longer SOCKS Server/Compare paths, multiple imports, other imported positions
and other requested graph families remain unfinished where not independently
implemented and verified. Their safe refusal is not completion of those
requirements. This change does not establish a complete current release or a
private deployment.
