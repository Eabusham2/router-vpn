# Desktop OpenVPN Server/Compare parent integration — November 16, 2026

The desktop public controller now carries an independently paired imported
OpenVPN middle through Server or Compare for complete 3–8-member paths. It
retains the original Local source, independent Server pairing, ordered packet
prefix, paired SS2022 final and saved source tokens. Eligible paths use the
existing typed OpenVPN preparation and physical owner; generic preparation is
not relabeled as schema 5. Unpaired imported OpenVPN remains a separate Local
path and does not acquire Server credentials from a public capability hint.

The parent keeps the exact preparation, original desktop policy, physical
owner, staged command, transfer identity and selected epoch through typed
adoption and Ready. Ready requires actual selected DNS/public proofs and the
original MTU/protection capture. The OpenVPN middle's public proof remains
visibly distinct from the paired private-node proofs. Saved restoration keeps
the selected winner and original source rather than starting a new Compare;
retirement remains joined to the captured native child and protection owner.

The existing editors and their complete-profile actions are retained exactly
from the separately published [editor unit](DESKTOP-OPENVPN-EDITOR-2026-11-16.md).
The parent connects those published capabilities to the
[native child](DESKTOP-OPENVPN-NATIVE-CHILD-2026-11-16.md),
[typed record protocol](DESKTOP-OPENVPN-EXECUTION-RECORDS-2026-11-16.md), and
[earlier packet-prefix measurements](OPENVPN-CANDIDATE-PREFIXES-2026-11-16.md).
Independent pairing remains operator-provisioned through the existing private
import/setup contract; this change neither manufactures pairing nor exposes
its private credentials in profile hints.
