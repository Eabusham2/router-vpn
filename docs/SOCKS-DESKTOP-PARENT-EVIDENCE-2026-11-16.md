# Typed SOCKS desktop Server/Compare parent — 2026-11-16

This unit connects the published schema-three SOCKS execution child to the
shipping desktop public controller, saved connection profiles, protection owner,
selected result, retained Last restoration, and macOS inherited process owner.
It preserves the complete original SOCKS source, including authentication and
UDP-association ownership; a generic or CONNECT preparation cannot replace it.

## Implemented source boundary

The admitted execution shape is exactly one paired WG/AWG packet entry, one
original SOCKS5 middle, and one paired Shadowsocks 2022 final. The entry retains
its independent canonical Off, AES-256-GCM, or AES-256-GCM plus XOR layer; the
middle and final remain Off. This is the current implementation boundary, not a
claim that broader requested ordered graphs are complete. Existing Local SOCKS
prefix support and the complete imported Shadowsocks execution prefix remain
separate. OpenVPN Server/Compare and arbitrary mixed imported execution graphs
are not added by this change.

The public method capability is `ordered_socks_trio_executions`; the distinct
per-profile source hint is `ordered_socks_execution_middle_supported`. Save,
Load, Update, public Connect, status, and restoration retain original profile
credentials and member identities. Source hints never grant a process or
physical permit. The original typed compiler, physical preparation, live child
receipt, selected proof, and retained process/network owner remain necessary.

Server and Compare both use the existing execution session. Compare's selected
execution, common endpoint, and fresh proof remain child-owned; restoration
uses retained Last and the selected MTU instead of rerunning Compare. Failed
child retirement retains the same owner for retry. A completed public request
does not revoke the retained connection, and a cancelled observer cannot supply
new authority. Darwin process arguments, host ownership, retirement, and MTU
capture retain the exact schema-three preparation and sealed physical pointer.

The Darwin protection dispatcher now admits this exact SOCKS execution trio
while validating every original saved member and the complete aggregate policy.
It still rejects longer SOCKS execution rows. Strongest-member Always protection
survives retirement and release. PF observations in the component fixtures use
an explicit temporary backend; they are not installed kernel acceptance.

## Required host gate

`deploy/build-native-runtime.py` requires
`test_desktop_socks_execution_controller_runner.py` and both baseline and causal
phases of `test_desktop_socks_execution_controller.py` on the matching native
host. Linux requires 139 baseline records, Windows 126, and Darwin 118. Darwin
runs its own captured retirement owner checks instead of a Windows child model.
The existing Windows ARM64 race exception is retained; other host phases use
`-race`. Each compiler retains its 240-second bound; each root retains its
120-second Go test bound and 135-second outer bound. Source and image identities
are checked around every baseline root and causal result. A target's native
execution cannot be inferred from another host or from a cross-compile.

Run the component gates from the repository root:

```sh
python3 deploy/test_desktop_socks_execution_controller_runner.py
python3 deploy/test_desktop_socks_execution_controller.py --go /path/to/go --phase baselines
python3 deploy/test_desktop_socks_execution_controller.py --go /path/to/go --phase controls
python3 deploy/test_native_shipping_audit_gates.py
python3 deploy/test_darwin_pf_journal.py
```

Installed Linux/macOS/Windows packet-path acceptance, Apple signing and device
execution, and any live router deployment remain separate evidence boundaries.
