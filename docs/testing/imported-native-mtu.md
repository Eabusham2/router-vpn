# Imported native entry to paired-final MTU

## Shipping path and ownership

The desktop Auto and Retest dispatch recognizes the retained imported native
entry and paired Router VPN final before the older external-node optimizer.
The shared private-node MTU controller now reaches that exact native TUN through
a dedicated desktop owner. It does not use the old unauthenticated UDP script.
The connection keeps its original graph, private final credentials, selected
DNS/device policy, native child, source, physical-network identity and TUN reader.
Imported OpenVPN additionally keeps its original authenticated remote,
generation and packet capacity.

The adapter owns the native begin/set/commit/rollback protocol and its one-shot
unconfirmed-commit revert. The same retained owner excludes ordinary selected-DNS
and OpenVPN observation mailboxes while the MTU lease is active. Measurement
sockets are bound to the observed native interface using the platform-specific
socket controls and exact readback. Only the captured paired private API and
its authenticated MTU sink are admitted. A partial dial returned with an error
is closed before it can enter retained socket ownership.

The existing shared controller selects at most five MTU candidates within the
captured graph’s per-hop envelope. Each accepted candidate requires six valid
authenticated packet-size replies and real 256 KiB upload/download transfers.
Private final-node proof is repeated through the candidate path. Auto may use
one historical hint only if its full path, network and profile fingerprints
match and it is at most 24 hours old; that hint is measured again. Retest bypasses
the hint. The stored measurement does not claim an outer underlay PMTU.

Public Cancel cancels the original operation. Failed or cancelled work retains
its exact native cleanup authority and cannot mutate a replacement connection.
A native commit that completes after cancellation uses the original revert
capability. The retained shared controller then restores the complete original
configuration and verifies the returned rollback reader, so another Retest does
not silently construct a fresh controller to hide stale state. Profile history
rollback changes only the exact measurement fields written by that operation;
newer credentials or another result are retained. Historical writes recheck the
original caller at the final atomic rename admission. Cleanup can release a
removed old workspace only after the exact native owner already recorded both
its closed state and verified child retirement; that release does not report a
measurement or restored interface.

Fixed policy remains the captured compiler policy and is not silently replaced
with Auto. Retest requires Auto without Jumbo. An unavailable private probe,
missing native owner, stale reader or changed physical path remains an explicit
failure; it cannot become a fabricated measurement.

final-rename and retained-retirement follow-ups. Its imported MTU selector
produced 84 passing and 3 failing verdicts, including the failed parent. The two

The retained native fixture published its status on commands only. It did not
refresh the heartbeat while actual HTTP body transfer was in progress, unlike
the shipping native loop's 250 ms heartbeat. On the slower integrated run the
host correctly rejected a record older than two seconds. The follow-up fixture
opt-in uses the same protocol implementation and refreshes only its retained
current record between commands. Existing negative cases keep the heartbeat
disabled so they cannot overwrite intentionally changed source, path, reader
or remote observations. A new causal case holds an actual private HTTP body
beyond the original two-second record lifetime: the refreshed fixture must
complete, while the unrefreshed fixture must fail without a measured or
restored claim. Production freshness limits and work/cleanup budgets are
unchanged.

The Windows contract workflow and authoritative release workflow now select
the entire `^TestDesktopImportedMTU` group on AMD64 and ARM64. The focused
workflow contract passed 19 Python tests, including negative mutations that
remove the group or restrict it to the older socket-only cases. This is a
workflow selection result; it does not establish a Windows build result.

## Protected Windows integration follow-up

A protected Windows imported launch runs a derived physical-policy graph.
The dependent integration validates the actual child file against that typed
policy while separately retaining the original imported envelope, entry/final
captures and native host. The original graph cannot replace the derived graph
for MTU planning, and a matching derived graph cannot excuse a changed original
envelope.

In the combined snapshot above,
`TestDesktopImportedMTUProtectedDerivedSourceCapture/shadowsocks` and
`.../wireguard` both failed the retained-process check. The modeled native
process's `Wait` returned immediately while the modeled child was still alive.
The shipping `desktopNodeProcessDone` correctly interprets a returned process
wait as completion, so a subsequent capture rejected that child. The fixture
repair makes `Wait` block until its retained completion channel closes or its
original caller cancels; `Close` closes that channel exactly once after writing
the original retirement receipts. No production process or source guard is
weakened. This follow-up still requires its corrected combined execution result
before it is accepted.
