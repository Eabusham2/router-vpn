# Imported entries with a paired Naive H2 final

The existing `naive-h2` mode is available as a paired Local final through a
captured imported entry. Shared Go, Android, Apple and desktop preparation use
the same source-bound compiler and native Naive transport. Daily connection and
temporary Speed Lab selection retain the original final, entry credentials,
selected DNS, protection, MTU and independent Start Layers. This adds no logical
mode and changes no default resolver or execution score.

## Captured graph

The separate inventory has nine wire variants: SOCKS5, Shadowsocks 2022,
Hysteria2, HTTP CONNECT, HTTPS CONNECT, WireGuard, AmneziaWG, OpenVPN TCP and
OpenVPN UDP. Each has three entry and three final Start Layer choices: Off,
AES-256-GCM, and AES-256-GCM with XOR whitening. Each independent producer must
supply all 81 original graphs; four producers require 324 native parses.

The paired final retains authenticated HTTP/2, verified TLS, the original server
address and port, username/password, certificate/SNI policy and version-2 UDP
over streams. H3, insecure TLS, missing credentials, a different transport,
unowned detours and missing private assets cannot inherit H2 authority. A
Shadowsocks 2022 predecessor must retain the exact cipher's valid key sizes and
identity-key chain; malformed encodings cannot enter through this new final.

HTTP/HTTPS CONNECT receives a distinct `naive-h2-stream` capability. It is not
an SS UoT service declaration or an Xray/VLESS capability. The original seven
compiler inputs remain sealed with their source fingerprint and compiled graph.
Changing a selected profile, source asset, API/token identity or layer cannot
reuse a captured graph or proof. An imported entry never receives the paired
final's private node identity.

## DNS and transport ownership

Application DNS uses the final Naive path. A selected TCP resolver uses an
authenticated stream; a selected UDP resolver uses Naive's version-2 datagram
stream. The separate resolver closure for the final's lower
transport retains the original selected endpoint, transport, port, TLS name,
path and query settings. Only the compiler's owned detour/tag references change.
An independently captured final Start Layer remains the lower resolver owner;
without that layer, its detour is the original imported entry.

The current CONNECT admission requires an explicitly captured TCP-compatible
lower DNS policy. The 81-graph inventories use explicit Home TCP. The compiler
does not convert the default Home UDP policy to TCP or replace it with a public
resolver. Whether an otherwise unused lower UDP resolver can safely remain
configured for an entirely literal H2 endpoint is a separate runtime question;
the current refusal is not evidence that this remaining compatibility
requirement is complete. UDP-capable imported predecessors retain their wider
selected DNS transports.

Native H2 transport must not issue an unrelated UDP probe through its lower
owner. IPv6 literals with a separate TLS name require the captured-literal
resolver policy described in the native Naive transport documentation. A saved
DNS selection, a parser pass or a zero-query literal test does not establish
that application DNS traversed the selected final. The native peer gate must
observe transport bootstrap and selected application DNS separately.

The connection still requires public-path, paired-node identity and selected
DNS proofs from the same current owner before Connected. Cancellation, network
change, teardown, stale measurements and source substitution cannot install a
result into a replacement connection. Temporary restoration retains its
already captured execution choice; it does not rerun Compare.

## Mandatory native and release gates

`imported-naive-h2-native.yml` requires the actual Apple exports, all nine
Android producer phases and desktop exports before the four native parser
inventories. Parser, encrypted loopback and imported physical-peer stages run
separately with finite, unchanged per-operation deadlines. Missing, renamed,
linked, duplicate, skipped, failed or changed evidence cannot satisfy a stage.

The focused workflow keeps the original ordinary, PQ and XHTTP jobs and adds
H2 after them. Release aggregation separately requires the real H2 workflow.
The executable aggregate checker rejects its removal, substitution, duplicate
job, conditional execution or ignored failure.

Every matching Windows, macOS and Linux x64/ARM64 completed or reused native
bundle must execute the H2 desktop producer, require its exact 82 verdicts and
81 unchanged graph files, then run that completed bundle's `check -c` against
each file. Original bytes and the complete bundle receipt are checked again
afterward. The prior 26 ordinary, 108 packet, 108 OpenVPN, 81 PQ and 81 XHTTP
inventories remain mandatory. Source/orchestration tests model subprocess
boundaries; actual completed-bundle acceptance is a matching-host build gate.

This extension does not close Naive H3, imported Server/Compare, additional-hop
composition, remaining Unix protected-host integration, signing, private
deployment or physical/off-LAN acceptance. A native interface/Netlink denial
remains a failed physical attempt; no simulated route or optional gate turns
it into acceptance.
