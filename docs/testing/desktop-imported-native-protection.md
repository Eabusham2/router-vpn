# Protected imported desktop connection

## Retained Windows parent and Speed Lab

Protected imported entry-to-paired-final connections now use a typed retained
parent and the corresponding native child. The parent captures all seven
private constructor inputs, authenticates the exact child and journal owner,
and keeps the original constructor alive through joined retirement. Protected
captures cannot silently fall back to the legacy helper. Partial startup is
published to the cleanup owner before entering the child, so cancellation and
failure retain responsibility for the entered work.

Daily connection and temporary Speed Lab execution use that same composition.
Speed Lab prepares the successor before suspending the predecessor, proves the
separate entry and final identities plus selected DNS, and restores the captured
execution choice and latest live MTU. An A-to-B-to-A restoration cannot borrow a
replacement process, constructor, connection operation or private workspace.
The parent also checks recorded cancellation intent before its asynchronous
cancellation callback is delivered.

The Auto/Retest eligibility and status paths replay the original sealed
constructor and use its merged MTU profile. This preserves restrictive proxy
entry Fixed/Jumbo policy instead of considering only the final node. A packet
entry with an independent fixed MTU still permits a compatible shared Auto
policy. Changed envelopes, derived graphs, entry policy or final credentials
cannot authorize the readback. These rules supplement the existing original
operation, network generation, rollback and cancellation guards.

This publication wires the retained Windows composition. The retained Linux
adapter is a separate implementation under validation; macOS retained imported
succession also remains separate. Existing generic Unix imported execution is
not evidence for those retained adapters.

## Source and admission

The Windows native child accepts imported-entry to paired-final graphs through
the explicit `--imported-source-sha256` family and private
`imported-source.json` envelope. This source flag is mutually exclusive with the
ordinary Node source flag. The child authenticates the inherited controller and
original journal pipe before reading either private constructor. It replays the
seven captured imported inputs, derives `DesktopImportedPolicy`, and compares
the exact derived source, config, restored MTU and staged graph bytes. It does
not retry another policy parser on failure.

The shared physical boundary accepts only the sealed concrete Node or imported
policy. The imported constructor remains distinct and live through physical
retirement. Final profile identity still binds journal admission; separate
entry and final identities, credentials and modes remain in the imported
capture. The existing Windows baseline, predecessor, durable commit and
retirement machinery retains the exact policy pointer and source capture.

## Actual native graph

Box preparation compares complete parsed shipping options with the independently
derived graph before its network service can construct an OS source. Imported
graphs own the captured TUN and two separate loopback proof listeners:
`multihop-entry-proof` routes to `entry-wg`, and `multihop-proof` routes to the
final `proxy` selector. Final selected DNS remains on the final path. Entry and
final LAN, IPv6 and MTU restrictions remain part of the immutable capture.

An imported SOCKS5 entry carrying datagrams uses the distinct
`routervpn-desktop-imported-socks5` outbound. Only its captured numeric TCP
control enters the static physical destination set. The existing native SOCKS
client authenticates a separate control connection for each operation before
the broker can grant that operation's negotiated UDP relay. A sibling, a later
native root or the ordinary Node family cannot borrow that relay permission.
Original per-operation close and mixed-failure handling are retained.

The imported entry and its actual Node lower carry the same caller context
through outbound, owner, manager and broker observations. A cancelled observer
returns while the original mutex remains held; it cannot leave a waiter that
later publishes a socket capability or cancel the healthy connection owner.
The native gate retains causal controls that restore each old ambient wait.

## MTU and retirement

Physical MTU replacement carries one original `mobilemtu` operation through the
owner lock, manager lookup, native readback, grant retirement and new binding.
An already-entered native transaction may finalize its returned rollback using
only the original remaining cleanup allowance. It cannot renew that allowance
from the connection lifetime. Repeating adoption reads the exact already
attached returned reader without rebinding. Native or policy failures cannot be
hidden by a cancellation retry.

Uncertain grant retirement revokes the original lifetime immediately through
`CancelAdmission`. Joined Box teardown retains the actual source and any entered
OS operation until its outcome is known. A still-existing TUN alone does not
establish a usable protected path.

## Executable coverage and limits

`deploy/test_desktop_node_physical.py` requires the imported command, native
factory, Box and SOCKS verdicts on Windows, including the individual altered
source and ownership cases. The command tests reject changed private entry or
final inputs, rehashed staged graphs, missing or mismatched restored MTU,
ordinary source records, conflicting flags and missing authenticated journals.
The Box tests construct real native managers and both actual proof listeners,
while replacing only the privileged TUN and OS socket source. The SOCKS tests
use real authenticated control and relay sockets with explicitly modeled
per-socket OS grants.

The cross-platform MTU tests exercise the actual native replacement manager,
including exact rollback, held locks, expired original cleanup and failure
after an entered grant retirement. Existing ordinary Node, external SOCKS,
DNS, admission and retirement suites remain required.
