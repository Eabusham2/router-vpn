# Apple paired Hysteria2 execution — November 16, 2026

The Apple ordered-path editor, captured connection identity and shared source
consumer now admit Server and Compare for the paired Hysteria2 family introduced
by `8f8e9fb3`. This continues the original mode, multihop, saved-profile, selected
DNS and complete-state ownership requirements. It does not reduce the remaining
protocol, graph or Start Layer requirements to this particular family.

## Source and user behavior

The supported source has two through eight original paired nodes. Every
preceding node keeps its selected WireGuard, AWG Fast or AWG Strong mode and its
own Off, AES-256-GCM or AES-plus-XOR Start Layer. The Hysteria2 final retains Start
Layer Off, its original endpoint, verified TLS name and private trust, password
and obfuscation. Each paired member retains its independently provisioned
standard WireGuard identity asset. Imported Shadowsocks, SOCKS5, CONNECT and
OpenVPN families keep their existing Shadowsocks-final contracts.

The editor uses the existing shared execution preparation and native host; it
does not create another system VPN. Saved profiles preserve every node reference,
execution choice, policy and original credential asset through Add, Load, Update
and Delete. Planned and active maps retain the original transport at every
position. The ordered measurement capture retains the complete source/config
identity and rejects replacement connection generations.

`IOSSessionIdentity` previously accepted only a Shadowsocks raw profile for a
captured execution. It now admits Hysteria2 while requiring the actual final
member's mode to equal that raw profile. Hysteria2 additionally requires the
paired schema, WG/AWG prefix and Off final. A captured Hysteria2 source cannot be
relabeled as Shadowsocks or another transport. Existing private source bounds,
canonical metadata, full node identities and imported-family validation remain.

The shared source validator also rejects a present Hysteria2 obfuscation object
without a supported type and nonempty password, matching the pinned native
endpoint's construction rules. Absent and null optional obfuscation remain
valid. Both supported type names retain their exact source parameters; source
preservation of a type is not a claim of a successful encrypted connection with
that type.
