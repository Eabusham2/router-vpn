# Selected-execution fifty-sample desktop consumer evidence

Date: 2026-11-16. Scope: the desktop parent and desktop consumer changes in this unit. Native producer, encrypted transport, packaged OS, and device acceptance are separate evidence.

## Behavior

The shipping desktop parent reads the capture published by the retained native selected-execution facade. It verifies the original typed Ready record, projection, reader, source and configuration fingerprints, selected Local/Server choice, full member inventory, and current session before issuing an operation. A refreshed validated heartbeat may update its timestamp and response timing; it cannot replace the captured proof generation, endpoint, MTU, comparison result, or selected execution.

The selected operation uses its own bounded request/cancel/result exchange. Every original request field is echoed, including the opaque native capture. Cancellation joins the original operation before releasing its MTU hold. A result is accepted only after the producer removes the original request and supplies a complete, drained fifty-sample receipt. The parent never repeats Compare selection to measure or restore the winning path.

Selected receipts use separate transactional durable history. They retain their complete captured identities and measurement meaning. An old or cancelled operation cannot overwrite a newer connection or newer durable history writer. The public edge response metric remains explicitly routed HTTPS response time; it is not described as ICMP latency or private-node response time.

Swift, PowerShell, and GTK consumers validate the selected capture together with every displayed row and receipt. Ordinary Local captures remain separate. This unit covers canonical two-to-eight-member selected paths, including their supported single imported penultimate member. Independent earlier/multiple imported selected paths are tracked in the separate schema-six extension.
