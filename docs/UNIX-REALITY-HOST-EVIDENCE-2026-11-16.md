# Retained Unix REALITY: source and native acceptance

Prepared November 16, 2026 UTC. This unit adds the single paired Router
`reality-vision`, `reality-pq-vision` and `reality-xhttp` paths to the retained
Linux/macOS host. The binding scope remains
[REQUIREMENTS-RECONCILED.md](REQUIREMENTS-RECONCILED.md); other outstanding
mode/graph/platform requirements remain outstanding.

## Shipping integration

The Linux dispatcher routes those exact modes through the existing owned
controller. The shared physical-graph admission and both Darwin PF state
parsers retain their captured mode through startup, readback and cleanup.
The existing Node compiler and native runtime retain the original node,
credentials, private trust, selected DNS, protection, MTU and restoration.
Off, AES-256-GCM and AES-256-GCM plus XOR whitening remain independently
captured Start Layer choices. Logical datagrams stay within the captured
Xray path; the physical policy admits the original TCP lower.

The shared tests derive the actual original Node profile and Linux/Darwin
policy for all three modes, layers and protection choices. They require
selected Home DNS through `proxy`, no substituted physical resolver or UDP
root, exact source ownership, and restoration of effective MTU without
changing the saved configured value or policy. Malformed mode aliases and
unproved families remain closed. See
[shared admission](../internal/mobilemultihop/desktop_node_admission.go) and
[actual policy tests](../internal/mobilemultihop/desktop_unix_reality_test.go).

## Mandatory native release gate

The [required workflow](../.github/workflows/unix-reality-host.yml) consumes the
same run's exact-source runtime bundle on Linux AMD64/ARM64 and macOS
Intel/Apple Silicon. Every target requires all three mode partitions. The
[executor](../deploy/test_unix_reality_host.py) first checks the complete
compiled inventory and 99 required fixture-contract records, then runs its
mandatory mode partition through the original installed controller.

| Target, per architecture | Vision | PQ Vision | XHTTP | Complete inventory |
|---|---:|---:|---:|---:|
| Linux retained host | 48 | 51 | 54 | 153 |
| macOS retained host | 36 | 39 | 42 | 117 |

These are native case inventories, not a count of completed product
requirements. The new gate retains selected DNS, private node proof,
wrong-key/user/SNI/short-ID refusals, PQ-key and XHTTP-path refusals where
applicable, independently captured outer-layer keys and whitening, original
protection, sealed restoration and joined retirement. Linux exercises actual
MTU lease commit/rollback and effective readback; Darwin additionally exercises
the existing Auto/Retest/Cancel benchmark lifecycle through the new modes.
Existing Linux inventories and the original 69-case macOS phase remain
mandatory and unchanged.

The fixture accepts only the original bounded Xray and wrapper files and
verifies the real peer's source, address, physical lower and counters. Its
fixed private proof/DNS/benchmark routes sit after the authenticated reference
Xray inbound and expose no general Internet route. Native helpers retain and
hash protected copies of the pinned Xray and actual shipping whitening
binary. All workers, listeners, connections, reference processes and captured
owners must retire through the original lifecycle. The complete source,
bundle, image and commit identities are checked again before a receipt is
written; the owned workspace must already have been removed.

The new workflow is required by the release aggregate. It cannot be selected
out by an optional input or a reduced case list. Original per-operation,
per-root and per-case deadlines are unchanged. The independent new phase has
its own bounded job budget.
