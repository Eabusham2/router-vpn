## Retained owner and protocol

The first actual latency facade supplies the opaque selected capture. Every
request retains the original activity, drains and closes that facade, then calls
`ValidateClosedCaptureContext` while the original measurement remains alive.
Only after those joins may a saved result be published. Cleanup retires the
measurement before its controller, native engine or MTU replacement retires the
underlying resources. Source, configuration, publication and request files keep
their original inode and byte bindings.

`node-chain-execution-latency-capture.json` contains schema 1, kind
`routervpn-node-chain-execution-latency-capture-v1`, the original typed Ready
object in `capture`, and actual opaque facade JSON in `selected_capture`.
The publication is immutable. Fresh typed Ready validates independently; its
association permits only a forward heartbeat timestamp and newly measured
positive finite prefix response durations. All other fields remain equal,
including comparison winner/scores, source, node identities, proof flags,
selection epoch, proof generation, reader and MTU.

The separate `node-chain-execution-measure-{request,cancel,result}.json`
mailbox leaves the ordinary grammar intact. Requests contain exactly schema,
operation (`selected-latency-50`), request_id, generation, deadline_at, path_id,
node_id, position, capture and selected_capture. Cancel contains the exact
request bytes. Result echoes these ten fields and adds status, completed_at
and optional saved receipt. Limits: 16 KiB request/cancel, 32 KiB publication,
8 KiB opaque selected capture and 128 KiB result.

both compiled controls. Baseline: one 600-second compiler and eight 120-second

phase. Controls: two 600-second compilers and 120/135-second executions;
maximum 1,470 seconds within 1,600. Local resources were two Go CPUs, GOGC 50

only this document changes. Later upstream changes add Python/workflow

That new shared Go API is an additive compilation input, has no initializer
or changed existing latency/runtime body, and is not called by this producer.
Composition alone is not a native rerun. Five lightweight strict runner tests
passed on the composed source; their synthetic records validate the parser,
source projection, inventories, causal anchors and registration only.
Root also independently ran the current desktop SOCKS source validator's 19
tests and CONNECT source validator's nine tests on the composed tree; all
passed. Those checks cover the retained upstream source-inventory fix and
negative controls, without compiling or exercising native transport.

The full baseline and both compiled controls on the published SHA remain
required for acceptance. Parent/UI integration, real encrypted transport,
installed-host and device gates remain separately scoped. Schema 6 Server/Compare
and selected throughput are follow-on work and are not admitted by this unit.
