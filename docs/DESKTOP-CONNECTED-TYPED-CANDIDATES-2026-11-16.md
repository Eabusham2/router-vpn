# Connected candidate measurements through original desktop SOCKS and CONNECT paths

## Behavior and requirement scope

The desktop candidate chooser can measure a replacement node through an earlier
packet prefix of an already connected Local SOCKS5, HTTP CONNECT, or HTTPS CONNECT
chain. The measurement retains the complete original typed source and native
runtime. It performs fifty routed TCP connection samples and reports their robust
statistics; these samples are not ICMP ping, throughput, or HTTP response timings.

This extends the shared typed plans published in `fc203c75` into the actual desktop
controller and generated native command loop. It does not grant a closed saved
prefix connected-session authority. Server and Compare execution owners, mobile
host adoption, real encrypted packet traffic and installed-device acceptance are
separate requirements.

## Ownership and restoration

The controller admits an exclusive SOCKS or CONNECT source family and validates
the exact Ready record, active TUN reader, MTU, session and source catalog. The
native command loop constructs its plan from the original proved runtime and
retains its measurement activity until the worker and callback have drained.

The typed exchange has distinct request, source, live observation, result and
cancellation files. A nonce, monotonic generation, captured source hashes and
owned file identities bind those files to one operation. A copied source list or
an old result cannot grant authority. Cancellation and replacement preserve the
original pending owner until cleanup joins; they cannot remove a replacement
operation's files. Generic candidate mailboxes remain refused by typed owners.

The final receipt must match the exact capture, prefix, candidate and original
candidate source; include all fifty successful samples; retain its original
expiry; and pass current source, connection and reader validation. Saving the
measured proposal retains the full selected typed graph and its settings.

## Verification record

The controller baseline compiled the complete `cmd/client` package with Go
1.26.3, the race detector and default vet. All thirteen new roots (151 records)
passed, as did thirteen existing saved-prefix roots (80 records) on the recorded
`aa458312` plus draft source. Three separately compiled omissions failed at their
intended assertions: dropping typed admission, dropping capture identity, and
allowing a saved-prefix purpose to grant connected authority. Those controls used
the recorded `fc203c75` plus draft source. Test and process deadlines were not
increased.

Those controller fixtures explicitly model the child process and kernel. The
later `684a1c27` widened ordinary imported-Shadowsocks plan admission; the two
affected old fixture roots require their separate updated proof-refusal check.
The earlier 80-record result is not reported as a test of that newer assertion.

Native command-loop and Box baseline verification passed all seventeen groups:
85 executed records covering 78 unique test names. The nine positive SOCKS5,
HTTP CONNECT and HTTPS CONNECT cases each used three-, four- or eight-node
graphs and fifty actual destination TCP connections, for 450 connections. The
remaining groups exercised admission refusals, cancellation, joined cleanup,
original Box ownership and reader/MTU checks. The complete command and Box
packages compiled with Go 1.26.3, the race detector and default vet. Compilation
and all seventeen groups finished in 658.163 seconds inside the original
900-second aggregate; the 150-second Go test and 600-second process bounds
were retained.

That baseline used exact checkpoint 8 on `684a1c27`; it is not represented as a
run of the newer tree. The guarded forward to `47e4cd58` preserved the published
paired Shadowsocks AES/XOR target rules and new native peer-layer inputs. Only
the owned controller catalog and native build registration needed three-way
merges. Four focused source/runner suites then passed 5, 9, 4 and 4 tests on
checkpoint 9. An independent source review found no concrete blocker in the
captured source, runtime owner, readiness, reader, generation or drain paths.

All three current-source native omission controls passed their strict causal
verdicts on `47e4cd58` plus checkpoint 9. Removing the generic-mailbox refusal,
typed Ready reader or original drain guard failed at the required assertion.
Each control compiled the complete native command package, retained race and
default vet, and preserved the existing clocks. The three controls finished in
151.828 seconds total. Their verifier rejects compiler errors, timeouts, panics,
races, unexpected tests and unrelated assertion failures.

The native component cases exercise original runtime proofs, actual Box inbound
ownership and MTU readback, and actual loopback TCP/TLS destinations. Their
packet transport and kernel TUN are explicit component models. They do not
establish encrypted packet transit, an installed device or a complete release.
