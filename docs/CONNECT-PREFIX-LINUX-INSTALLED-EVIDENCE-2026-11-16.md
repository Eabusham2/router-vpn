# Installed Linux CONNECT execution through complete packet prefixes

This unit adds a required installed Linux acceptance gate for the published schema-four CONNECT Server and Compare family. It covers two through six original paired WG/AWG packet prefixes, one literal authenticated HTTP or HTTPS CONNECT source, and the original paired SS2022 final using UoTv2. The existing independent 14-case CONNECT gate retains one-prefix coverage. The 27 imported-SS and 16 SOCKS installed gates remain unchanged and required.

The new 40-case inventory contains 30 positive cases: each prefix count two through six, HTTP and HTTPS, Server and both Compare winners. Every positive case suspends the original selected owner through the real Speed Lab coordinator and restores the retained winner and endpoint with a fresh native identity. It requires no repeated comparison and exactly one new Server worker, or no Server worker for a retained Local winner. The remaining ten cases at six prefixes cover wrong first and later packet keys, original proxy credentials, TLS server name, paired final key, public identity, selected DNS, replaced source, changed native carrier, and held cleanup with the same retained retry owner. Prefix modes include WG, AWG fast and AWG strong. These longer installed cases use layer Off; the existing trio gate separately retains its layer coverage.

The provider retains complete global positions and original private/public proof owners. Local and Server packet clients have independently generated keys. Only the exact captured TCP predecessor reaches the literal CONNECT listener; the middle and final do not acquire raw UDP authority. Server suffixes require the real native packet carrier and are not admitted through the portable-carrier test exemption. Original protected executable identity, source and native bundle receipts are checked across the run. HTTP administration and direct launch of the original shipping worker remain explicit fixture adapters, not private-server deployment proof.

The independently launched native worker keeps its normal certificate verification and sanitized environment. The generated public-proof and HTTPS proxy CAs are supplied by a read-only bind of the captured trust file inside the original worker's private mount namespace. Admission checks the original distinct namespace, worker interface and address; cleanup unmounts the bind after original workers join and verifies the original system trust inode. The test does not rewrite production TLS configuration or disable certificate verification.

The reusable workflow runs on Ubuntu 24.04 amd64 and arm64 against the caller's exact native runtime bundle and is a mandatory release aggregate dependency. Only the exact 40 new cases receive the already established CONNECT execution limits of 240 seconds inside Go and 250 seconds for its process. The new workflow's aggregate budget accounts for all forty cases and preparation; existing per-case and unrelated workflow limits are unchanged. The verdict parser requires every original case, exact typed traffic/proof counters, one package PASS, and all four successful namespace retirement phases. Skips, missing or duplicate records, foreign records, races, fatal or signal aborts and incomplete retirement are refusals.
