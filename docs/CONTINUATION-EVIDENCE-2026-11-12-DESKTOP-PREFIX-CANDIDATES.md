# Desktop retained-prefix candidate ownership

This source increment connects the existing sealed candidate plan to the
original desktop native child. It does not create a replacement tunnel or
infer a candidate's private authentication from a successful TCP connection.
The companion HTTP job and native UI increments are tracked separately.

## Runtime and catalog contract

The parent captures the complete private saved-source inventory, exact file
identities, saved-policy catalog generation, original connected session,
physical-network generation and retained native reader. The native child owns
the actual candidate service. Private request/source/live/cancel/result files
are bounded and linked within the original protected workspace. A renewable
parent pulse is valid only while the captured source and session remain live;
polling cannot renew a completed result's 120-second expiry.

The existing candidate boundary remains literal Off SS2022 sources through a
retained paired WG/AWG packet prefix. Every scored receipt requires exactly
fifty successful destination TCP connections, finite consistent statistics,
the exact captured candidate and prefix, a complete receipt and joined native
work. Partial, failed, replaced or stale work receives no score. This measures
TCP connection time, separately from HTTP response time, ICMP RTT, throughput
and the Local/Server comparison formula.

Candidate work shares the original measurement/MTU hold. If the bounded drain
cannot complete, the returned error retains the exact original cleanup handle;
later retries cannot look up or retire a successor through mutable selection.
A late or repeated finish callback also cannot release a newer measurement's
hold. Original process/workspace retirement can acknowledge only the matching
retained cleanup handle.
