# Typed SOCKS desktop execution foundation

This increment adds a distinct schema-3 desktop Server/Compare preparation,
physical policy, adoption record, readiness record, saved Last binding and native
construction. The original `DesktopNodeChainSOCKSPolicy` remains the authority
for the complete source, target, session, TUN MTU, lower transport and original
SOCKS association. The independently paired final remains unchanged. The desktop
source is not admitted through the CONNECT or generic paired parser.

The preparation keeps application forwarding closed. Its original physical
policy pointer survives the authenticated in-place execution transition. Selected
DNS follows the execution selector while retaining the original resolver and
bootstrap policy. Static physical analysis removes only the verified original
desktop lower wrappers, then requires the same entry tuple inventory. The imported
SOCKS control and negotiated UDP association stay behind that entry; no proxy
address gains a direct physical permission, and the original final is not
converted to CONNECT/UoT.

Private adoption and heartbeat records bind the same original preparation,
physical source, transfer, selected epoch, Box/network/session identity and
observed interface/MTU. They grant no process, socket, TUN or lease authority by
themselves. The parent must still check its original live native owner. The saved
Last record retains the selected Local or Server result and original endpoint;
fresh discovery and selected-path proof remain necessary after retirement.

The separate native construction captures the original preparation, physical
policy, SOCKS source, caller-local registry and association owner before parsing
the complete native graph. A copied construction, foreign preparation/policy,
changed source or registry, canceled context, or ordinary Local construction
cannot borrow it.

## Executed shared evidence

With Go 1.26.3, `-race`, `-p=1` and the unchanged 180-second package bound, the
new `^TestDesktopSOCKSExecution` suite passed in 43.935 seconds. It covers all
desktop targets, all three paired entry modes across Server/Compare, both proxy
authentication modes, unchanged original members and physical scope, exact
canonical records, copied/foreign owners, changed derivation metadata, rejection
of longer execution topology, and retained Last restoration. Its Last case runs
the actual HTTP/TLS administration, authenticated Manager and proof logic; the
native route, DNS and worker boundaries are explicit fixtures.

Focused existing-family regressions passed in 82.970 seconds: CONNECT desktop
construction/transition/Last, original SOCKS execution, retained mobile SOCKS MTU
restoration, and the new generic imported-public capture. The concurrent Apple
generic execution capture and native public dispatch are preserved.

## Native construction result

The exact source passed through a fresh canonical desktop preparation
of sing-box `1ac1a339cb1223e9c70eae14c44411c75033c02d` and Xray
`50231eaff98ccc31b5cbd247a721c16e97fe5ec1`. The actual `cmd/sing-box` native gate
passed both original roots and all 20 root/child records under `-race`. A compiled
overlay removing only the original construction identity check made the copied
construction case fail at its intended witness. The original prepared source was
unchanged. The two baseline roots completed in 3.70 and 7.12 seconds respectively.

All 15 changed shared Go sources, after the canonical preparer's declared import
relocation, and both new native construction templates were compared byte for
byte with the prepared core used by that gate. The run used the
ordinary full desktop native tags, Go 1.26.3, two compiler workers, `-p=1`,
`GOGC=50` and a workspace temporary directory. It did not create a live TUN or an
OS firewall lease.

The gate runs for every shipping desktop host before packaging. It retains the
existing 120-second test bound and separate 600-second compiler/process bounds.
Race remains enabled on supported targets, with the existing Windows ARM64
toolchain exception. The runner's seven checks require complete, unique,
successful records and reject missing cases, skipped/racing/failed work, foreign
or late events and partial output. They also require the gate in the common
shipping host branch, independently of the platform-specific acceptance suites.

## Remaining adoption

This increment does not enable public desktop SOCKS Server/Compare. The native
platform physical activation, child/parent session and retained MTU transfer,
public Connect/profile controls, and installed encrypted acceptance still need
to adopt these distinct owners. Native construction and shared models do not
establish kernel, installed TUN, encrypted path, or device acceptance. The supported
SOCKS Server/Compare topology remains the exact paired packet entry, one imported
SOCKS middle and paired final trio. Full historical requirements remain broader.
