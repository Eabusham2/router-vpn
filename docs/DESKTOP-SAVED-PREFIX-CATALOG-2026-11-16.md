# Desktop saved-prefix candidate catalog

The saved-prefix chooser previously built the connected full-path candidate plan
before constructing its own closed preparation. Longer saved paths containing a
penultimate external Shadowsocks member therefore failed at the wrong admission
boundary, even when the shared prefix-only constructor accepted the complete source.

The chooser, preparation, fresh-source checks and runtime recapture now select the
exact requested scope. A prefix catalog retains its own immutable preparation and
has no connected candidate plan. The operation retains that exact preparation
owner, the complete original source, all saved candidate files, catalog revision,
network identity and cancellation lifetime. Fresh recapture must match the original
closed source. Ordinary connected and complete-path catalogs keep their existing
independent admission rules.

Only the selected paired packet prefix can become runnable. The imported suffix and
original final remain complete Save provenance, including their DNS/device-policy
restrictions. This change grants no application ingress, DNS forwarding, Connected
state, or connected measurement authority. It does not admit typed SOCKS/CONNECT
original captures; those require their separate typed preparation constructors.

## Validation

The full shipping controller test package compiled with race instrumentation and
vet on `1c5a0ab79322c7f8c8f3890f1830423c25a4411a` plus this scoped change. The
seven complete selected roots passed all 29 records. They exercise the actual
chooser, catalog, preparation, closed native projection, source recapture and unused
retirement for four/eight-node literal and hostname Shadowsocks paths. Refusals
cover complete-scope substitution, imported/final positions, equal-valued foreign
preparation ownership, changed scope, candidate credentials, final source bytes and
a replacement physical-network observation. Existing ordinary complete preparation,
prefix cancellation and receipt-purpose tests remain passing.

A compiled counterfactual restored the actual former chooser call through the
connected catalog. The four-node literal positive test then failed with the exact
expected chooser-refusal witness, exit 1, and no timeout, race, abort or missing test.
The passing controller and counterfactual used the same flags and original bounds.

These are executable source/controller tests, with an explicit physical-network
observation fixture. No child process, VPN packet, private DNS request, physical
device or installed native widget was exercised by this unit. Actual encrypted
native prefix tests and exact-SHA release gates remain separate requirements.
The complete Go source gate discovers both new roots from the compiled test image.
