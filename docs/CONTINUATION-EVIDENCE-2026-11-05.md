## Integrated original-caller observations

Commit `a94cde9d` connects the original observation context
through shipping command projections, native Box identity, inbound and network
receipts, physical owner/broker/PT observations, selected graph/cover proofs,
server leases and the actual pinned OpenVPN client/endpoint state.

- Context-aware capabilities are explicit. Missing support is an integration
  error, not permission to call an unbounded legacy reader.
- Pure caller cancellation/expiry cannot adopt a late receipt or retire a
  healthy connection. Confirmed owner/graph failure revokes the original
  admission immediately, including a real failure joined with cancellation.
- Revocation does not synchronously join held cleanup locks. Original owners
  retain cleanup and Close/Stop joins; replacement owners are not affected.
- External/Tor commands watch their original Stop capability independently of
  a blocked receipt reader. The watcher retains the original directory,
  session and source identity and is joined on exit.
- Linux network observations retain the original dump/ACK stream and exact
  interface/address identity. Sent requests are drained after cancellation.
  Darwin and Windows observations retain original locks and pre/post context
  checks; fixed OS inventory syscalls are not claimed interruptible.
- Tor heartbeat adopts one complete MTU/network receipt only after matching
  interface name, index and MTU, rereading the original MTU revision and checking
  the same caller. Mismatch, revision-only ABA and late cancellation preserve
  the prior receipt.
- Windows identity publishes its verified original owner once through an
  immutable atomic pointer. Observation never waits on its publication mutex;
  capture equality, validity, closing state and freshness remain required.
- Native dependency projection preserves exact pins and source/tamper checks.
  The shared observation-error classifier is projected narrowly, without
  exposing unrelated common-package files to native builds.

## Native MTU operation admission and original cleanup

The commit containing this section connects bounded MTU capture, command-mailbox
admission, status, cancellation, cache commit, native replacement and restoration.
The accepted command retains its original lifetime and transported absolute
deadline; a short maintenance poll cannot cancel it or give it a new deadline.
Tor registration and worker publication share one generation. If an admission
acknowledgement arrives after the polling caller expires, that accepted worker
is still published for owned cleanup but is canceled before measurement.

Each admitted operation has one lazily activated cleanup allowance. Native
replacement, failed-candidate retirement, readback, physical rebind and rollback
share its remainder. A cleanup read cannot renew it. Late candidate results
cannot become winners, and a missing/expired allowance or replaced owner cannot
report successful restoration. A valid original owner still restores after
cancellation: the actual returned transaction is retained even when cancellation
prevented ordinary post-change observation. Unused rollback-reader closure cannot
publish an expired winner or resurrect the closed rollback reader.

The final combined prepared native composition includes the already-published
FD11 launch changes. It passed all 47 required parent/leaf verdicts under race
across generated mobilemtu, inbound manager, TUN, native command and Box
finalization packages. Both Darwin architecture TUN packages compiled with the
changed native control methods. The merged routing runner passed 39 checks and
the Tor audit passed 42 checks. Earlier focused causal controls rejected lost
authorized rollback, late publication, renewed cleanup, held manager/startup
admission, lost finalization retry and a live worker after late admission.

These results cover the accepted native MTU command and its transport. The
earlier client snapshot/proof-dispatch chain still has contextless observation
dependencies; a separate client closure is being implemented and tested. The
installed persistent service still needs its actual operation worker and public
Retest/Cancel integration. Neither requirement is closed by this native unit.
The original Tor authenticated reply drain retains its separate five-second
ownership allowance; fixed native syscalls are not claimed hard-interruptible.

## Installed Linux service: original operation channel foundation

Commit [`f76382cf`](https://github.com/Eabusham2/router-vpn/commit/f76382cf57fb9c12851b5962a108b49beaf31f51)
adds FD11 to the actual service launch and
fixed native child. The original sealed capture binds its device, inode, size
and layout. Startup verifies the child's acknowledgement against the exact
authenticated Ready receipt. Original FD10 retirement remains unchanged.

FD11 has a fixed 12,648,448-byte layout: a 64-KiB control region and 32 bounded
transaction records, each with separate Ready and retirement pages for the
original, candidate and rollback readers. A record reserves capacity before
construction; later reader bindings must describe the actual retained readers.
A failed partial reader can have retirement evidence without an invented Ready.
Raw evidence pages preserve the existing 16-KiB native receipt parser limit.

Work and cancellation use separate local locks and original process-level file
lock regions. Cancellation remains available when the work deadline has expired
or another process holds the work region. Shared inherited open-file-description
locks cannot substitute for those process locks. Stable reads, canonical frame
digests, original keys, non-reusable sequence/slots and exact retained descriptors
reject torn, replayed or substituted evidence. The native child closes FD11 only
after retiring its original native resources; the service joins its original
child before closing its copy.

Focused validation passed 59 standardengine race verdicts, including ten new
operation-channel parent tests, six original startup-fixture leaves and four
mandatory service-runner checks. The actual inherited child and process lock
tests execute real descriptor inheritance and interprocess locking. Replacing
only the process lock with an open-file-description lock failed the intended
cross-process exclusion assertion. The complete generated Linux AMD64 command
composition compiled with the five changed shipping inputs. Startup routing
effects in the fixture are explicitly modeled; this is not a real TUN mutation
or installed-service acceptance result.

This foundation exposes no public MTU action and performs no candidate mutation.
It deliberately has no reset/reuse operation: future settlement must join the
worker and receive acknowledgements from both original observers before another
request can be admitted. The service observer and native tracker are the same
object; the controller request observer is the second one. FD11 evidence cannot
create either observer's authority.

### Preserving already-proved service observers after an expired read

Commit [`d4a37bb4`](https://github.com/Eabusham2/router-vpn/commit/d4a37bb4b7a5866bf7cf7b50631d6fb6a0fe7c2d)
made the service network observer and controller request observer distinguish a
pure expired observation from confirmed source, namespace, reader or lifetime
loss. A pure expired read leaves the same already-proved observer usable for a
later call. A real failure joined with cancellation remains permanently latched.
The controller's source read acquires the original application mutex within the
same caller context; it cannot leave an unbounded waiter or accept a replacement
application after the wait.

Original startup admission is stricter: cancellation during bind, Begin or final
admission still invalidates that startup. This change does not grant a new
observer, bypass original connection intent or implement service MTU mutation.
The focused actual privileged/race selection passed 28 test verdicts, including
eight service observer cases, eight controller observer cases, three startup
cancellation leaves and five existing proof-failure leaves. Original children,
sealed sources, namespaces and authenticated channels are real; event delivery
uses the existing explicit model. Reverting the two production files failed five
intended observation cases. Removing only the final startup failure latch failed
the final-admission case. The merged mandatory service runner passed four checks.

Commit [`2f2149e1`](https://github.com/Eabusham2/router-vpn/commit/2f2149e16952b1f1983ef2019acdb9d6dab5238f)
carries this distinction to the actual
background caller. It classifies the returned error before canceling its own
observation context. Pure read expiry keeps the same original engine and reader
for the next poll; confirmed reader failure joined with expiry still retires the
original engine and retains its On-connect protection.

The actual shipping watcher passed both cases under race in 13.024s, using real
child/peer ownership, sealed configuration and selected-DNS exchanges with only
event delivery modeled. Restoring only the old watcher reproduced unintended

The regression remains mandatory in the service runner. This does not certify
every controller-monitor admission or mutex path; those remain separate caller
