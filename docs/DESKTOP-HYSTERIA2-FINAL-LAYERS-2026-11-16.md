# Desktop Hysteria2 final Start Layers

Date: 2026-11-16. This is a bounded completion of the requested independent
Start Layer choice for a paired Hysteria2 final. The full product requirement
ledger, installed-device acceptance and exact published release remain separate.

## Behavior and ownership

The actual Windows, GTK and AppKit editors admit Off, AES-256-GCM and
AES-256-GCM plus XOR whitening for a paired Hysteria2 final after the original
WG/AWG prefixes. The actual desktop source and execution compiler retains the
complete two-to-eight-node selection for Local, Server and Compare. Invalid
layer strings or types, duplicate identities, imported-middle restrictions and
changed original credentials remain rejected. An editor choice does not grant
runtime proof by itself.

Saved profiles retain the full selected source inventory and final layer.
Startup/Last receipts explicitly serialize a non-Off Hysteria2 final layer, and
validate the exact original WG identity, Hysteria2 source and SS layer source in
order. The canonical Off receipt omits the new optional field and retains its
previous serialization. A source digest alone cannot authorize a new final
layer, and a different valid layer cannot borrow the original captured owner.

The final layer remains independent of each preceding node's layer. Hysteria2
credentials, Salamander, TLS server name and private trust remain the captured
values. Existing public-connect, Compare, physical-policy, cancellation,
retirement and restoration paths are exercised with their explicit native-child
and kernel-observation doubles; encrypted transport acceptance belongs to the
separate real-provider gate.
