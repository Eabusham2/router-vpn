## Original source and typed API

`NewNodeChainOpenVPNExecutionPreparation` accepts the original captured `*NodeChain`; `ParseNodeChainOpenVPNExecutionPreparation` reopens its canonical typed preparation. The schema-5 preparation has exactly `schema`, `execution`, `local_source`, and `openvpn_local_launch`. The last field retains the complete original sealed Local launch, including an existing iOS/Android projection. A generic source or preparation parser cannot admit this family. `OriginalOpenVPNSource` returns only the validated original pointer. `NewNodeChainOpenVPNExecutionPolicy` requires that same preparation and the independently paired Server descriptor.

The private binding compares its exact preparation/source/middle pointers, current source seal, original sealed launch and every retained immutable pair/capture field. It freshly validates the complete original source on every observation. `NodeChainOpenVPNExecutionObserver` and `NodeChainOpenVPNEngine` remain separate required native interfaces. The owner observer validates the original construction even while the Local provider is pending or has refused authentication. Only a Local trial additionally requires and retains its actual connected remote/MTU observation; later changes are refused, and a blocked receipt lock retains the caller's deadline. Entry discovery and a Server trial retain native construction ownership without depending on unrelated Local authentication. Server still requires its independent authenticated lease and original public/final/DNS proofs. No immutable input seal replaces a live endpoint observation.

Discovery preserves original global packet positions and independent Server source identities. Local and Server middle hashes intentionally differ and are joined only by the canonical provider-pair digest. Shared proof, selected DNS, comparison target/mean, original lease, failed cleanup, selected hop measurement, Last and mobile restore retain their existing ownership checks. Mobile restore changes only the issued original TUN readback through its opaque process-owned capsule; it requires original shared/native retirement and fresh discovery before adoption. It cannot be reconstructed from JSON or a caller-provided MTU.

## Evidence boundary and follow-on

These tests execute the actual shared compiler, strict parser, discovery, authenticated loopback HTTP/TLS proof/Manager path, comparison, measurement facade, restore and cleanup state machines. Native OpenVPN endpoint, OS TUN/readback and remote worker boundaries are explicit doubles in this shared suite. The separate Server native unit provides its own real encrypted component evidence.
