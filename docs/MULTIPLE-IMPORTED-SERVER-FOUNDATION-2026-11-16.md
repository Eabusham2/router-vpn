# Multiple imported Server source and relay foundation

This unit adds distinct operator-owned schema-six Server plan and source constructors for a paired packet entry, one or more independent literal SS2022 interior imports at their original positions, any remaining paired packet interiors, and a paired Shadowsocks final. `NewNodeChainMultipleImportedServerPlan` consumes complete independently selected Local/Server bundles. `NewNodeChainMultipleImportedServerPolicy` reparses its exact private suffix source. Generic Server and client execution constructors retain their existing admission boundaries.

Every imported row retains its original source digest, profile identity, public proof role and expected public IP, with no fabricated Router API, credential or packet identity. Paired Server clients retain independent private packet keys. Relay requests carry exactly the complementary Local packet positions: entry position zero plus every paired non-final position, excluding every imported row and the final. Each suffix position keeps its own front credential. The final application DNS digest and original descriptor/capture ownership remain exact. Schema-one through schema-five digest domains and positional contracts are preserved.

A private scope binds the original Server policy, source, members, policies, nodes and compilation closures. For an SS-first suffix, the first actual packet retains the existing nonpacket-root configured-capacity policy; the omitted client entry is never invented as an outer packet interface. Later packet edges retain the full original nested carrier envelope. Each real proof/application/selected-DNS projection must remain inside the original first transport's exact tuple set, and their aggregate must equal the complete set. A subset, added tuple, missing projection or substituted owner is refused. Local and legacy per-projection equality remain unchanged.

## Evidence boundary

The public proof tests execute authenticated private HTTP, verified public TLS, distinct original imported public IP responses, selected-DNS identity checks and owner-change refusals. Their native dial/DNS interface is a controlled route double. Relay tests execute the real manager, capture and receipt validators with controlled worker replies. Native carrier acquisition, worker/Box schema-six dispatch, retained client preparation and restore, selected measurement metadata, desktop/mobile factories and host admission remain separate integration requirements. This unit does not widen those boundaries or claim a green full release.
