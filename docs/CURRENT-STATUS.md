## Current selected-route work

The current source repairs full-route ownership, private-final history restoration, and desktop candidate timing validation. Windows, macOS, Linux, Android, and iOS retain the complete selected route and its original Local or Server winner when reopening measurements. Compare Local preserves its own response authority; a Server response cannot be substituted under that catalog.

Desktop clients with the installed native engine expose Local, Server and Compare for the registered ordered public-final family. Android and iOS retain their distinct native owner for the same execution preferences. This family has a paired packet entry and independently registered literal-address Shadowsocks 2022 suffixes with the final Start Layer Off. Connected and selected routes with an imported SOCKS5, HTTP/HTTPS CONNECT or OpenVPN penultimate hop can measure an authenticated paired Shadowsocks final replacement through the original prefix. This recovery preserves the original source and winning execution; it does not permit inserting another hop. Hostname public finals, other final protocol families, custom entries and additional mixed or layered compositions remain separate unfinished capabilities.

Android and iOS live public-final responses use three fresh HTTPS responses, bound to the original Local owner or selected Local/Server execution. A changed or retired owner invalidates its result. These live responses remain separate from the saved 50-response node statistics and retain the same original measurement service.

The selected-route Speed Lab retains the original winner, complete node inventory and public-final identity through status, download/upload measurement, result display and cleanup. It uses the original 8 MiB transfer in each direction. Native network checks and controller/UI capacity checks have distinct scopes: the longest native latency paths exercised 96 members, and the native throughput checks exercised three members with independently counted bytes at every peer.

Recursive Local candidate timing retains the complete captured registry when a packet hop appears before or after an imported Shadowsocks member. Android and iOS can also measure eligible literal-address Shadowsocks candidates through the selected first paired entry while a public-exit draft is still incomplete. Those candidates use their original saved TCP port; changed sources, sessions or network decisions invalidate the result. The mobile Performance action opens the original routed per-hop and final-path speed measurements.

A complete Local route of two to eight paired nodes can measure a replacement final through its original WG/AWG prefix when every Start Layer is Off. A connected route keeps its selected final active. For a dormant profile or complete unsaved draft, the temporary controller proves only the selected prefix and keeps application and DNS ingress closed. The saved final can be offline. In both cases the candidate must use the exact final mode, one of Hysteria2, WG, AWG2 Fast or AWG2 Strong. The benchmark requires fifty fresh authenticated private-agent responses. Hysteria2 retains its TLS trust. Packet candidates require independent client and server keys and the same nested MTU as their future route. Cancellation retains the measurement scope until the endpoint and its UDP work have joined. Save preserves the prefix and raw mode in a separately named profile for a future connection.

Local paths with three to eight paired nodes can also measure an intermediate WG, AWG2 Fast or AWG2 Strong replacement in the successor's exact raw mode when the retained final is Shadowsocks or Hysteria2. The existing nine-to-96-node all-WG-to-Shadowsocks family supports WG intermediate replacement under its complete-source authority. A connected route uses its original active owner. A dormant complete profile or unsaved complete Local draft uses a separate temporary prefix with application and DNS ingress closed. Both retain the complete original prefix and suffix. Save creates a separately named profile; after the original temporary owner finishes cleanup, Use can replace that one intermediate in the same complete unsaved draft. Final replacements remain named-profile saves. Source identities remain distinct on catalog, measurement, cancellation and adoption responses. Server and Compare packet candidates, imported or layered packet successors, external finals and incomplete packet drafts retain their separate unfinished scope.

## SMART startup and restoration

Installed Linux clients can trial lighter transports from the bundled WG-PQ or Naive H3 wrapper with Kill Switch Off, after capturing the original graph and live tunnel MTU. A failed candidate must finish cleanup before the captured path can restart and earn a fresh proof. A firewall guard that appears during rollback is preserved. The single-node PQ startup and restoration budgets include the existing first-key window and remain bounded by the original connection operation.

With On-connect or Always, a new WG-PQ or Naive H3 connection on an installed native Linux client starts under the retained controller. The same owner can then stage the lighter transport or restore the captured source, selected DNS and live MTU. Start Layer Off, AES-256-GCM and AES-256-GCM with XOR whitening retain their separate original credentials. An older protected wrapper keeps its working connection when its guard cannot transfer.

Home LAN Off preserves the original paired Router API's exact private TCP endpoint through the selected encrypted node. Other private hosts and ports remain subject to the captured LAN policy. The exception does not create a physical socket allowance, change the selected DNS policy or bypass IPv6 Off. The original selected tunnel still has to earn its independent private-route health proof.

The Linux release jobs qualify these transitions against independent protocol peers using the packaged controller, a real foreground login and stock PolicyKit authentication, actual TUN interfaces, and continuous firewall and leak observations. Each architecture runs 18 cases; the two architectures cover 36 complementary transport/layer/policy/outcome combinations. This source is not qualified until those installed checks pass on both targets. See [mode behavior](MODES.md).
