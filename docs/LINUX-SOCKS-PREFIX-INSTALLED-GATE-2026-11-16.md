# Installed Linux SOCKS prefix execution acceptance

The release aggregate now requires an additional installed Linux SOCKS execution gate on both amd64 and arm64. It uses the captured shipping controller and native worker, TUN, nftables, owned network/mount namespaces, original encrypted providers and an authenticated SOCKS control/UDP association. Its private administration endpoint and direct worker launch are explicit fixture boundaries; it does not claim private-server deployment.

## Required scenarios

The new gate retains 28 distinct installed cases. Fifteen positive cases cover two through six packet prefixes with explicit Server execution and both Compare winners. The mode rotation exercises WireGuard, AWG Fast and AWG Strong at every supported prefix count and retains independent original keys and parameter fingerprints at later positions. Thirteen controls cover first/later packet keys, SOCKS authentication and downgrade, negotiated relay domain and route, control EOF, public identity, final key, selected DNS, source replacement, carrier mutation and held cleanup.

Each positive path restores its already-proved concrete winner without rerunning Compare. Counters bind the actual original prefix positions, modes, parameter hashes, native carrier, selected DNS and independent final proof. SOCKS retains its negotiated UDP association; CONNECT/UoT evidence cannot satisfy this gate. After Disconnect, the worker must already be joined before the provider acknowledges retirement. The provider must observe natural control EOF and join its own leases; shutting down the provider cannot manufacture a zero-association result.

The existing sixteen installed SOCKS trio cases and their source/workflow remain unchanged. The new 28-case gate adds coverage for longer paths rather than replacing those cases. It retains the original per-case bounds: 240 seconds for the Go case, 250 seconds for the namespace and 265 seconds for its outer process; native compilation remains bounded at 300 seconds. The new workflow has a finite aggregate budget of 170 minutes within a 180-minute job.

## Local evidence and limits

On source base `3360e07798625e168b1ca3be72bc3e0a85ea4c53` plus the thirteen frozen changed files, the real native peer compiled with race instrumentation in 97.581 seconds and the privileged controller package in 213.181 seconds. Both retained their original 300-second compilation limits.

All 36 required native component records passed across four roots: original source positions, independent provider positions, malformed/private-source refusals and real SOCKS authentication/UDP-association retirement. The peer used the existing canonical native checkout read-only. Comparing current shipping copy/relocation outputs found 859 byte-identical derived files; an explicit two-file overlay supplied the published desktop prefix admission guard and the new peer test.

The strict new receipt/orchestration validator passed 21 tests, the workflow guard seven, and the aggregate gate 31. The original SOCKS trio validator passed 18 and the existing CONNECT prefix validator 19. Full artifact/workflow parity passed. The 13 tested outputs were integrated with the current Apple inputs and then rebased onto `539cf805d9565f9d25532856988f35232f709bc6`, preserving its Server transport-lifetime repair. Twelve tested outputs remain byte-identical; the builder adds the four new identity inputs while preserving every existing current input.

The 28 full installed kernel scenarios have not run in this local environment. They remain mandatory hosted release gates. Component success, native compilation and synthetic negative receipt tests do not establish installed networking, physical-device acceptance, private deployment or a green release.
