The subsequent three-file CONNECT addition is published at `658414f3`, on the
actual published `d0b99255` runtime and `1fdaeea0` profile dependencies. It
preserves `http-connect` and `https-connect` separately and routes the same

final's SS UoT-v2 service declaration and selected Home DNS remain required.
This closes the earlier pending CONNECT candidate Save description for that
bounded graph; it does not admit arbitrary insertion positions or transports.

A candidate result and a complete connection profile have different authority.
The full proposed path must compile from the current original sources before
Save. Its record references the correct private nodes instead of copying their
secrets. A changed candidate source between Test and Save invalidates the
operation; a later explicit Load uses the still-linked current node credentials
and the saved complete policy. Save must not replace the active session, node
catalog or runtime.

Both the connected and the prepared workflow share this requirement. Prepared
Save additionally requires the original temporary owner to have joined and
returned Home to DOWN. The existing profile transaction remains atomic:
publication failures roll back the new record and cannot mutate another
connection or the original catalog.
