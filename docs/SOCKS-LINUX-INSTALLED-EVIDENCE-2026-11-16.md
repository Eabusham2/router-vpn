# Installed Linux SOCKS Server and Compare gate

This unit adds a required native amd64/arm64 Linux acceptance gate for the published schema-three SOCKS execution family. The supported graph remains exactly one paired WG/AWG entry, one imported authenticated SOCKS5 middle, and one paired SS2022 final. It does not widen the graph or authorize a live private-server deployment.

The new provider fixture retains the original packet entry and paired final identities. Its actual SOCKS listener negotiates a distinct UDP socket under each authenticated original TCP control. The entry packet path admits only those live negotiated relay tuples. It does not grant UDP authority from a configured TCP port, substitute CONNECT, or wrap the final in UDP-over-TCP. The original shipping relay process implementation and lease-handler implementation are projected unchanged; the separate fixture launcher requires schema three and `SOCKSServerDevice` from the original typed SOCKS suffix. It rejects `NativeCarrierRequired`, which identifies a WG/AWG-first server suffix and must remain false for the SOCKS association family. HTTP administration and direct launch of the captured shipping executable remain explicit fixture adapters.

The 16 required installed cases cover WG and both AWG modes, entry Off/AES-256-GCM/AES-256-GCM plus whitening, Server, both Compare winners, and fresh retained restoration. Refusals cover wrong original credentials, authentication downgrade, a domain relay reply, a foreign advertised relay, TCP control EOF, wrong public identity, wrong paired final key, and failed selected DNS. Additional cases replace the original source and hold cleanup to prove bounded refusal with the same retained owner. The gate requires actual encrypted entry and final counters, authenticated public TCP and negotiated UDP counters, original selected DNS, exact comparison score and endpoint, fresh restoration without a second comparison, and joined worker/control/association retirement.

The reusable workflow consumes the current caller's exact native bundle on Ubuntu 24.04 amd64 and arm64. Both jobs are mandatory release aggregate dependencies. Exact source and image identity are checked before and after the native cases; durable receipts require a published commit. No case filter or optional success path is exposed. Existing CONNECT and generic host gates remain separate. Only the exact 16 new scenario names receive the established CONNECT execution budget of 240 seconds inside the test and 250 seconds outside it; all other guardian budgets retain their original values.
