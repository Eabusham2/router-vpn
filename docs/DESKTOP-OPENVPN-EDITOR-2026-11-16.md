# Desktop OpenVPN ordered editor — November 16, 2026

The Windows, macOS and Linux ordered editors now retain a separately paired
OpenVPN intermediate when selecting Server or Compare. This continues the
original ordered custom-node, complete connection-profile and execution-choice
requirements. It connects the public editor contract to the distinct native
child published in `d4fc8d41`; public controller adoption is a separate unit.

## Editor contract

A path contains three through eight nodes: one through six independently
linked WireGuard or AmneziaWG prefixes, the original OpenVPN intermediate,
and a paired Shadowsocks 2022 final. The OpenVPN intermediate retains Start
Layer Off. Every paired prefix and the final retain their own canonical Off,
AES-256-GCM or AES-256-GCM plus XOR whitening choice.

Server and Compare require the exact boolean public capability
`ordered_openvpn_execution_middle_supported` for that imported source and
the controller's distinct `ordered_openvpn_executions` capability. Generic,
Shadowsocks, CONNECT or SOCKS capabilities cannot authorize this path.
The controller remains responsible for validating the original literal
OpenVPN transport and independent Local/Server provider pairing. Missing or
nonboolean hints fail closed; a display hint cannot create a native owner.

Editor requests contain the original ordered references, selected execution,
selected final identity and source-token inventory. They do not copy private
provider credentials. A relinked or replaced member cannot inherit an older
draft. Complete profile save, load and update retain the selected path and
execution without implicitly connecting. Existing Local and other protocol
families retain their original capability checks.
